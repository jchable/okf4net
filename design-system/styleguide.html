The §Document.

The OKF4net site has one idea: every page is a concept document. Editor-tab navigation, a framed document window, ## chapter markers with § spec references, a raw⇄rendered duality. This page is the system's mirror — it renders the real stylesheet, so it can't drift from what ships.

##

Foundations

tokens — the only values you may use

Colour. One brand hue (Klein blue), near-black ink, and a narrow set of neutrals. Every colour is a CSS variable in :root; never hard-code a hex in a page.

--white #ffffffpage background
--ink #101014text, borders, code blocks
--blue #1a3fd6brand — links, accents, primary
--blue-soft #eef1fdtints — fm cells, code, hovers
--gray #6a6a72secondary text
--hair #e3e3e8hairline borders
--ok #0e8a4dsuccess, YAML strings

Inside pre.block (dark) the syntax palette shifts to hold contrast on ink: .k #7e9bff keywords · .s #ffd166 strings · .c #7a7a85 comments · .ok #6fd18a success.

Type. Three families, three jobs. Never introduce a fourth.

display — Inter Tight, 800/900, tight tracking · h1, h2, blockquote, cta
Knowledge is a directory of markdown files.
body — Inter, 400/500/600, 16px / 1.6 · prose, lede, lists
Load a bundle, check conformance, walk the cross-link graph. Bundle.Load never aborts on a bad file — parse failures land in ParseErrors.
mono — Space Mono, 400/700 · nav, labels, paths, code, data
okf validate ./my_bundle → OK: conformant with OKF v0.1

Layout & rhythm. One centred column, .frame at max-width: 1200px with fluid gutters (clamp(16px, 3.5vw, 48px)). Prose measures are capped (64ch body, 44ch blockquote) for readability. Borders are 1.5px solid ink for structure, 1px hair for internal grids. Zero border-radius — the system is orthogonal by design.

##

The metaphor

every page is a concept document
If you can cat a file, you can read OKF — so every page looks like a file you could cat.

The whole identity derives from the product. Pages don't decorate; they impersonate an OKF concept document:

  • The top navigation is a strip of editor tabs — each link is a *.md concept id, the current page marked with an inset blue underline.
  • Content opens inside a framed document window (.doc-window) with a chrome bar showing the file path (my_bundle/page.md) and its type:.
  • The home hero carries a live raw ⇄ rendered toggle — the same duality OKF has between markdown source and its rendered view.
  • Chapters are numbered with a ## markdown-heading badge and annotated with the spec section they map to (§4–§5).

Structure encodes something true: the § references are real spec citations, the file paths are plausible concept ids, the sidebar in /docs is a real bundle tree. Decoration that doesn't map to the product gets cut.

##

Patterns & guardrails

how to assemble a page

Page skeletons. Two openings, one body.

SkeletonWhen
hero + raw/renderedHome only — the marquee concept document with the live toggle and site.js.
.page-docEvery subpage — a slimmer document window (path + type + h1 + lede), no toggle.
.docs-shellReference pages under /docs — bundle-tree sidebar + the .page-doc opening.

Below the opening, content is always a .docbody of section.chapter blocks, each led by a .chead.

Responsive. Three stops. At 960px the editor-tab nav is hidden and the docs sidebar stacks above content. At 720px the frame goes full-bleed: it drops its gutters, the document window loses its side borders, and code blocks bleed edge to edge while text keeps a 16px inset.

Accessibility floor (non-negotiable):

  • Visible keyboard focus everywhere — :focus-visible draws a 2px blue outline; never remove it.
  • prefers-reduced-motion disables smooth scroll and all transitions.
  • Ink-on-white and blue-on-white clear WCAG AA; the dashed .conform badge and .tag chips are never the sole carrier of meaning.
  • Every interactive tab and toggle exposes state (aria-current, aria-pressed).
