### Addendum — revue de code approfondie (2026-07-28, post-approbation)

Avant d'écrire le plan, revue complète du code source (pas seulement les README) de `src/OKF4net.Agents/`,
`src/OKF4net.Catalog/`, `src/OKF4net.Catalog.Hosting/` via 3 agents d'exploration en parallèle. Deux
résultats notables :

1. **Le contenu ci-dessous (Phases 2 et 3) était sous-spécifié sur plusieurs points** — corrigé dans les
   phases révisées ci-après (§ mis à jour) plutôt que par un second document séparé.
2. **Dérive documentaire trouvée et corrigée en dehors du site**, pendant cette même session : `README.md`
   et `src/OKF4net.Catalog/README.md` décrivaient la mémoire scoped `role:"memory"` comme un "V2 preview
   (not implemented)" — faux, livré depuis la 0.2.0. Une PR #35 ("session/tenant memory tiers") mergée dans
   `dev` **pendant cette session** a déjà corrigé ces deux README ; il restait `CLAUDE.md` (ligne 41) et le
   commentaire XML de `MemoryTier.cs`, corrigés séparément (commit `36ce8bb`, hors du travail "site" mais
   découvert par la même revue). **Fait important pour le contenu du site** : les trois tiers
   (`Session`/`User`/`Tenant`) sont désormais implémentés de façon générique par `FileMemoryStore` — ce
   n'est plus "seul `User` est implémenté".

#### Inventaire vérifié — `OKF4net.Agents`

- **9 tools** (`OkfBundleTools.GetTools()`), chacun documenté ci-dessous avec son contrat exact (jamais de
  throw — tout est converti en chaîne `"Error: ..."` par un wrapper commun) :
  `okf_read_concept` (ligne méta `status | trust | stale` seulement si non-défaut), `okf_browse`
  (sert `index.md` brut si présent, sinon listing généré), `okf_graph`, `okf_search` (score = titre×3,
  tags/description×2, corps×1 ; top 20 ; tag `[deprecated]`/`[stale]`), `okf_write_concept` (délègue à
  `BundleConceptWriter.WriteConcept`, cœur `OKF4net`, partagé avec la mémoire scoped), `okf_append_log`,
  `okf_regenerate_indexes`, `okf_validate_bundle`, `okf_changes_since`.
- **`OkfContextProviderOptions`** — table complète à documenter (le README n'en liste que 4 sur 9) :
  `TokenBudget` (int, défaut `2000`, estimation `chars/4`), `MemoryCapture` (`MemoryCaptureMode`, défaut
  `Disabled`), `MemoryDirectory` (string, défaut `"memory"`, **`[Obsolete]`** — dépréciée au profit des
  sources catalog `role:memory`), `MaxConceptsInjected` (int, défaut `5`), `ScopeAccessor`
  (`Func<InvokingContext, KnowledgeAccessScope>?`, défaut `null` ⇒ `Local` — contrat "jamais dérivé d'un
  message" ; si l'accesseur hôte lève, l'exception **n'est pas avalée**, seule dérogation volontaire à la
  garantie "jamais de throw" du provider), `CaptureTier` (`MemoryTier`, défaut `User`),
  `KnowledgeBudgetShare`/`MemoryBudgetShare` (double, défauts `0.6`/`0.4`, doivent être ≥0 et sommer à ≤1),
  `StalePolicy` (défaut `Use`).
- **`MemoryCaptureMode`** — confirmé : seulement `Disabled`/`Enabled` dans le code vivant ; `SharedBundle`
  n'existe plus que dans le CHANGELOG (historique, normal) et d'anciens docs de design archivés.
- **`BundleConceptWriter`** vit dans **`OKF4net` (cœur)**, pas dans `Agents` — c'est le primitif
  atomique/verrouillé/anti-reparse-point partagé par `OkfBundleTools` et `FileMemoryStore`.

#### Inventaire vérifié — `OKF4net.Catalog`

- **`catalog.json`** — champs par source : `id` (requis, segment `ConceptId` valide, unique),
  `path` (requis), `priority` (int, défaut `0`), `enabled` (bool, défaut `true`), `role` (`"knowledge"`
  défaut, ou `"memory"`), `tier` (requis **seulement** si `role:"memory"`, une valeur parmi
  `"session"`/`"user"`/`"tenant"` — **toutes trois implémentées**, pas seulement `user`). Codes de
  diagnostic (`CatalogDiagnosticCode`, liste fermée) : `ParseError`, `UnknownRootProperty`,
  `UnknownSourceProperty`, `WrongVersion`, `EmptySources`, `DuplicateSourceId`, `InvalidSourceId`,
  `EmptyPath`, `EmbeddedNul`, `MalformedPriority`, `MalformedEnabled`, `IllegalRole`, `IllegalTier`,
  `DuplicateMemoryTier`, `InvalidPath`, `AbsolutePath`, `OutsideRoot`, `TargetNotFound`,
  `ReparsePointInPath`.
- **`FileKnowledgeCatalog`** — fail-fast (`CatalogException`) sur manifeste initial invalide ; reload
  errors-as-data (`LastReloadDiagnostics`, jamais de throw) ; swap de snapshot atomique sous un seul lock ;
  `Generation` (long) incrémentée uniquement sur un reload **réussi** ; watcher `FileSystemWatcher` +
  debounce (250ms défaut) sur le fichier manifeste seul, best-effort (erreurs avalées pour ne jamais tuer le
  process) — `ReloadAsync` reste le seul chemin garanti.
- **`DefaultKnowledgeResolver`** — confirmé : résultats groupés par source (triées par `priority` desc puis
  `id`), **aucune fusion/dédup cross-source**. Ne cherche que les sources `Enabled && Role == Knowledge`
  (les sources `Memory` ne sont jamais cherchées ici). `StalePolicy` de la `KnowledgeQuery` appliqué après
  collecte, sur l'ensemble combiné des passages.
- **`KnowledgePassage`** porte `TrustTier` (défaut `Unverified`) et `Lifecycle` (struct avec `Status`,
  `StaleAfter`) — **`IsStale` n'est pas un champ**, c'est une méthode (`Lifecycle.IsStale(DateOnly)`),
  appelée par `StalePolicy.Admits`.
- **Mémoire scoped** (`IMemoryStore`/`FileMemoryStore`) — lecture unions les tiers applicables
  **du plus spécifique au moins spécifique : session → user → tenant** ; écriture cible un seul tier ;
  `DeleteScopeAsync`/`EnumerateAsync` pour RGPD/audit ; `MemoryPath.For` encode chaque segment en
  `{minuscule}-{hash SHA256 tronqué}` pour éviter les collisions insensibles à la casse sur Windows/macOS.

#### Inventaire vérifié — `OKF4net.Catalog.Hosting`

- **`AddKnowledge(this IServiceCollection, Action<KnowledgeOptions> configure)`** — enregistre
  `IKnowledgeCatalog`/`IKnowledgeResolver` en singleton via `TryAddSingleton` (paresseux : aucune I/O tant
  que le premier `GetRequiredService` n'a pas lieu). `configure` doit appeler `KnowledgeOptions.AddCatalogFile(path)`
  **exactement une fois** (0 appel ou 2+ appels lève une exception synchrone dès `AddKnowledge`).
- **`AddMemory(this IServiceCollection)`** — **absent du plan initial, à ajouter au contenu de la page
  Catalog.** Enregistre `IMemoryStore` (singleton), nécessite qu'`AddKnowledge` ait déjà enregistré
  `IKnowledgeCatalog`. **Limite V1 à documenter explicitement** : le jeu de racines mémoire est figé à la
  *première* résolution du conteneur — un `ReloadAsync()` ultérieur du catalogue ne met pas à jour les
  sources `role:memory` utilisées (contrairement au resolver de connaissance, qui relit `Current` à chaque
  recherche). Vérifie aussi, en échec rapide, qu'aucune racine mémoire ne chevauche une racine knowledge.

## 1. Objectif

Aligner le site public (`jchable.github.io/okf4net`) sur l'état réel du projet en `dev` : conformité
OKF v0.2, package `OKF4net.Agents` (9 tools + `OkfContextProvider` + mémoire scoped), package
`OKF4net.Catalog`/`.Catalog.Hosting`. Le site doit rester un **bundle OKF** cohérent avec lui-même (chaque
page se présente comme un concept `.md`) — les nouvelles pages suivent le patron établi (`PageDoc`,
`Chapter`, `MapTable`, `ConceptGrid`, `Steps`, `Tag`, etc., `web/src/components/doc/`).

## 2. Hors périmètre

- Le bump de `README.md` "Mapping to the spec" (repéré en §0, incohérence pré-existante) — corrigible dans
  une PR séparée, indépendante du site.
- `CliVersion` (`"0.1.0-alpha.1"`) — ne bouge pas, c'est un artefact de versioning CLI distinct du spec.
- Contenu §10 Attested Computation implémenté côté core — dépend d'un futur design ; le site se contente de
  refléter l'état "not yet implemented".
- Tout contenu marketing/outreach (`docs/outreach/`) — hors périmètre "site produit".

## 3. Architecture — 5 phases

Chaque phase est un lot cohérent, testable indépendamment (`npm test` + `tsc -b` dans `web/`), livrable en
une PR ou en plusieurs petites PRs séquentielles. Ordre recommandé : 1 → 2 → 3 → 4 → 5 (le rebrand mécanique
d'abord pour ne pas re-toucher deux fois les mêmes lignes de version ; Agents avant Catalog car c'est le
trou de contenu le plus visible ; spec en dernier car elle dépend du tableau §0 déjà stabilisé ici).

   séparé ; `StalePolicy` (`Use`/`Strict`/`Tolerate(n)`) sur `KnowledgeQuery`, appliqué après collecte sur

## 4. Risques / points d'attention

- **Exactitude du contenu Agents/Catalog** : le README est la source de vérité la plus riche, mais toute
  affirmation sur le comportement (ex. sévérités de validation, valeurs par défaut) doit être vérifiée
  contre le code (`src/OKF4net.Agents/`, `src/OKF4net.Catalog/`) au moment d'écrire, pas recopiée
  aveuglément — le README peut lui aussi dériver (cf. §0, la table spec du README est déjà un exemple de
  dérive).
- **Compteur de tests** : ne pas écrire un chiffre sans l'avoir vérifié (`dotnet test`) au moment de
  l'implémentation — les tests continuent d'être ajoutés.
- **`references/` convention (§6.3)** et **§10 Attested Computation** : nouveaux dans le spec v0.2, mais pas
  encore dans OKF4net — le site doit être honnête sur ce qui est implémenté vs. ce qui ne l'est pas, sans
  quoi il induit en erreur un lecteur qui teste un bundle avec ces champs.
