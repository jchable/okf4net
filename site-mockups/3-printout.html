OKF4NET

Knowledge is a directory of markdown files. This is its .NET toolchain. zero dependencies · 182/182 tests · byte-exact

Name

okf4net — a zero-dependency C# implementation of the Open Knowledge Format (OKF) v0.1: a library and an okf CLI to parse, validate, index and graph bundles of markdown concepts.

Built entirely on the .NET base class library — its own YAML-subset parser, markdown link scanner, directory walker and argument parser. If you can cat a file, you can read OKF; if you can git clone a repo, you can ship it.

Synopsis

okf validate <bundle>     # §9 conformance, non-zero exit for CI
okf info     <bundle>     # concepts, types, links, version
okf index    <bundle>     # (re)generate every index.md
okf graph    <bundle>     # cross-link graph, --dot for graphviz
okf parse    <file>       # print one document's structure
okf fmt      <file>       # normalize: parse + re-serialize (-w writes)

Ships as a self-contained Native AOT single-file binary. No .NET runtime required on the target machine.

The format

bundle
A directory tree of UTF-8 markdown files — the unit of distribution.
concept
One markdown document: YAML frontmatter delimited by ---, then a body.
concept id
The file's path with .md removed: tables/users.md → tables/users.
cross-links
Ordinary markdown links, absolute (/tables/users.md) or relative (./other.md). Backlinks are derived.
index.md, log.md
Reserved filenames — generated directory listings and date-grouped change history.
conformance
One hard rule: a non-empty type on every concept. Everything else — unknown types, unknown keys, broken links — must be tolerated.

Library

using OKF4net;

var bundle = Bundle.Load("./my_bundle");     // never aborts: errors are collected
var report = BundleValidator.Validate(bundle);

var id = ConceptId.Parse("tables/orders");
foreach (var b in bundle.Backlinks(id))      // who cites this concept?
    Console.WriteLine($"cited by {b}");

Contributing

Prerequisite: the .NET SDK. That is the whole list — zero third-party runtime dependencies is a design rule; contributions keep it that way.

  1. Fork; branch from main.
  2. Add or update tests. The suite is the contract — including byte-exact golden comparisons of CLI output. (Never let a formatter touch tests/fixtures/.)
  3. dotnet test and dotnet format --verify-no-changes must pass. Warnings are errors.
  4. Open a PR; cite the spec section (§) for behavioural changes.

Issues and requests: github.com/jchable/okf4net/issues
